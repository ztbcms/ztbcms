
### 5.2.3 实际安装发现

安装过程中发现 easywechat 4.x fork 与 TP8 生态有 PSR 包版本冲突，需注意以下约束：

| 包 | 原计划版本 | 实际版本 | 原因 |
|---|---|---|---|
| `topthink/think-orm` | `^3.0\|^4.0` | `^3.0`（v3.0.34） | think-orm v4.0 要求 `psr/simple-cache ^3.0`，与 easywechat 的 `^1.0` 冲突 |
| `nesbot/carbon` | `^2.66` | `^3.0`（v3.13.1） | TP8 生态已依赖 carbon 3.x，降级不兼容 |
| `psr/log` | 自动 | 锁定 `^1.1`（v1.1.4） | easywechat 要求 `^1.1`，TP8 框架兼容 |
| `psr/simple-cache` | 自动 | 锁定 `^1.0`（v1.0.1） | easywechat 要求 `^1.0`，TP8 框架兼容 |
| easywechat-composer | 无 | 需 `allow-plugins` | composer.json 中需配置 `allow-plugins.easywechat-composer/easywechat-composer: true` |

> **结论**: think-orm 必须使用 v3.0.x，不能用 v4.0.x。这对业务代码无影响（TP6 用的是 v2.0.x，v3.0.x 是 TP8 兼容版本）。

| 考虑 | 说明 |
|------|------|
| fork 已可用 | Jayin 的 fork 已修复 PHP 8.3 兼容，可直接使用 |
| 6.x 重写成本高 | 官方 6.x API 完全不同，重写所有调用代码工作量大且引入回归风险 |
| 4.x fork 可控 | 自行维护意味着可以按需修复，不受官方停止维护影响 |
| TP 无关性 | easywechat 不依赖 TP 的 ORM/路由/模板，TP 版本升级不影响它 |

## 5.7 依赖安装顺序

建议按以下顺序逐步安装，每步验证：

```bash
cd tp8

# Step 1: 核心框架（已由 create-project 安装）
# topthink/framework ^8.0
# topthink/think-orm ^3.0|^4.0
# topthink/think-filesystem ^2.0|^3.0

# Step 2: TP 生态包
composer require topthink/think-multi-app:^1.1
composer require topthink/think-view:^2.0
composer require topthink/think-queue:^3.0
composer require topthink/think-migration:^3.0

# Step 3: 低风险第三方包 + easywechat (fork)
composer require firebase/php-jwt:^6.4 guzzlehttp/guzzle:^7.3
composer require predis/predis:^2.0 nesbot/carbon:^2.66
composer require phpmailer/phpmailer:^6.3
composer require aliyuncs/oss-sdk-php:^2.4 alibabacloud/client:^1.5
composer require qiniu/php-sdk:^7.14
# easywechat 通过 VCS fork 安装，已在 repositories 中配置

# Step 4: 开发依赖
composer require --dev topthink/think-dumper:^1.0 topthink/think-trace:^2.0
```
