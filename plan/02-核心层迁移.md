# 阶段 2: 核心层迁移 — 框架耦合文件适配

> **目标**: 将 tp6 中所有直接依赖 ThinkPHP 框架内部 API 的文件逐个适配到 TP8。
> **前置**: 阶段 1 完成，`tp8/` 骨架已就绪。

---

## 2.1 文件清单与优先级

| 文件 | 优先级 | 耦合度 | 说明 |
|------|--------|--------|------|
| `public/index.php` | P0 | 高 | 入口文件，TP8 可能有变化 |
| `think` | P0 | 高 | CLI 入口 |
| `app/provider.php` | P0 | 高 | 容器绑定，影响全局 |
| `app/ExceptionHandle.php` | P0 | 高 | 异常处理，基类可能变更 |
| `app/Request.php` | P1 | 中 | 请求对象扩展 |
| `app/BaseController.php` | P1 | 中 | 所有控制器基类 |
| `app/AppService.php` | P1 | 中 | 服务注册 |
| `app/common.php` | P1 | 低 | 自定义函数，框架 API 少 |
| `app/event.php` | P2 | 低 | 事件定义，格式可能微调 |
| `app/middleware.php` | P2 | 低 | 中间件定义 |
| `app/service.php` | P2 | 低 | 服务注册文件 |

## 2.2 逐文件适配指南

### 2.2.1 `public/index.php` — 入口文件

**tp6 版本**:
```php
namespace think;
require __DIR__ . '/../vendor/autoload.php';
$http = (new App())->http;
$response = $http->run();
$response->send();
$http->end($response);
```

**适配要点**:
- TP8 入口文件格式基本不变，但需确认 `App` 类构造方式是否有变化
- 如果 TP8 支持链式调用 `(new App())->http->run()->send()`，可保持原样
- 复制后直接测试，如报错再调整

**操作**:
```bash
# TP8 骨架自带的 public/index.php 通常已适配，优先用骨架版本
# 然后确认功能一致
diff tp6/public/index.php tp8/public/index.php
```

**适配要点**:

### 2.2.3 `app/provider.php` — 容器绑定

**tp6 版本**:
```php
use app\ExceptionHandle;
use app\Request;

return [
    'think\Request'          => Request::class,
    'think\exception\Handle' => ExceptionHandle::class,
];
```

**适配要点**:
- TP8 容器独立为 `think-container ^3.0`
- 绑定接口 `'think\Request'` 和 `'think\exception\Handle'` 需确认是否仍为相同全限定名
- 如果 TP8 改用了 `Psr\Http\Message\ServerRequestInterface`，绑定方式需调整
- **先保持原样**，运行测试确认，如报错再修改

**操作**:
```bash
cp tp6/app/provider.php tp8/app/provider.php
# 运行后如果报 "Class not found"，检查 TP8 中对应接口名
```

---

### 2.2.4 `app/ExceptionHandle.php` — 异常处理

**tp6 版本关键代码**:
```php
use think\exception\Handle;
use think\exception\HttpException;
use think\exception\HttpResponseException;
use think\exception\ValidateException;
use think\Response;

class ExceptionHandle extends Handle
{
    protected $ignoreReport = [
        HttpException::class,
        HttpResponseException::class,
        // ...
    ];

    public function report(Throwable $exception): void { ... }
    public function render($request, Throwable $e): Response { ... }
}
```

**适配要点**:
- TP8 的 `think\exception\Handle` 基类仍存在，但方法签名可能微调
- `render()` 返回类型 `Response` 需确认 TP8 的 Response 类路径
- `$ignoreReport` 属性是否仍被支持
- `json()` 助手函数在 TP8 中仍可用
- **重点关注**: `DataNotFoundException`、`ModelNotFoundException` 的命名空间可能从 `think\db\exception` 变为其他位置

**操作**:
```bash
cp tp6/app/ExceptionHandle.php tp8/app/ExceptionHandle.php
# 测试：触发一个 404 和一个验证错误，确认异常处理正常
```

**可能需要的修改**:
```php
// 如果 TP8 移动了异常类命名空间
// 旧: use think\db\exception\ModelNotFoundException;
// 新: 检查 TP8 vendor 中的实际路径
```

### 2.2.6 `app/BaseController.php` — 控制器基类

**tp6 版本关键结构**:
```php
abstract class BaseController
{
    protected $request;
    protected $app;
    protected $batchValidate = false;
    protected $middleware = [];

    public function __construct(App $app)
    {
        $this->app = $app;
        $this->request = $this->app->request;
        $this->initialize();
    }

    protected function validate(array $data, $validate, ...) { ... }
    static function createReturn(...) { ... }
    static function makeJsonReturn(...): Json { ... }
    static function returnSuccessJson(...): Json { ... }
    static function returnErrorJson(...): Json { ... }
}
```

**适配要点**:
- **构造函数**: TP8 可能改用属性注入（PHP 8 构造器提升），需确认 `App $app` 参数是否仍为标准方式
- **validate() 方法**: TP8 的 `think\Validate` 已独立为 `think-validate ^3.0`，命名空间可能变更
  - 旧: `use think\Validate;`
  - 新: `use think\Validate;`（通常不变，但需确认）
- `$this->app->parseClass('validate', $validate)` 方法在 TP8 中是否仍存在
- `Json` 响应类 `think\response\Json` 命名空间是否变更

**操作**:
```bash
cp tp6/app/BaseController.php tp8/app/BaseController.php
# 测试：访问任意一个控制器 action，确认构造函数正常
```

## 2.4 Facade 使用扫描

在 tp6 代码中搜索所有 Facade 调用，确认 TP8 中是否仍可用：

```bash
cd tp8
grep -rn "think\\\\facade\\\\" app/ --include="*.php"
```

**常见 Facade 对照**:

| Facade | TP6 | TP8 状态 |

| `think\facade\Config` | ✅ | 通常不变 |
| `think\facade\View` | ✅ | 需确认 |
