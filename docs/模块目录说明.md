# ZTBCMS 之模块开发文档

## 模块概述

ZTBCMS 是一个基于 ThinkPHP 6 的模块化内容管理系统，支持模块的独立开发、安装和卸载。每个模块位于 `tp6/app/{模块名}/` 目录下，拥有独立的控制器、模型、服务、视图和数据库表。遵循 ThinkPHP 6的多应用模式。

系统模块（`admin`、`common`、`install`）为框架核心，不可卸载。

## 模块目录结构

以下是一个完整模块的标准目录结构（以 wechat 模块为参考）：

```
tp6/app/{模块名}/
├── Config.inc.php          # [必须] 模块配置文件
├── middleware.php           # [可选] 模块中间件配置
├── config/                  # [可选] 模块配置目录
│   └── xxx.php
├── controller/              # [可选] 控制器目录
│   └── admin/               #   后台控制器（子目录按功能分组）
├── model/                   # [可选] 模型目录
├── service/                 # [可选] 服务层目录
├── view/                    # [可选] 视图模板目录
├── libs/                    # [可选] 模块工具类库
├── cronscript/              # [可选] 定时任务脚本
├── job/                     # [可选] 队列任务
├── install/                 # [可选] 安装目录
│   ├── {ModuleName}.sql     #   数据库建表 SQL
│   └── Menu.php             #   后台菜单配置
└── uninstall/               # [可选] 卸载目录
    └── {ModuleName}.sql     #   数据库删表 SQL
```

> 除 `Config.inc.php` 外，其他目录和文件均为可选，按模块实际需求添加。

## 核心文件说明

### Config.inc.php（必须）

模块配置文件，定义模块的基本信息。安装时系统读取此文件获取模块元数据。

```php
<?php

return [
    // 模块显示名称
    'modulename'  => '微信开发',
    // 模块图标 URL
    'icon'        => 'https://example.com/icon.png',
    // 模块简介
    'introduce'   => '公众号、小程序、第三方平台',
    // 模块文档地址
    'address'     => 'http://doc.ztbcms.com/module/',
    // 作者
    'author'      => 'Jayin',
    // 作者网站
    'authorsite'  => 'http://ztbcms.com',
    // 作者邮箱
    'authoremail' => 'hi@ztbcms.com',
    // 版本号（仅包含数字和点号）
    'version'     => '1.0.0',
    // 适配的最低 CMS 版本（安装时会做 version_compare 检查）
    'adaptation'  => '4.0.0',
    // 签名（可选）
    'sign'        => '',
    // 依赖模块（可选，数组格式）
    'depend'      => [],
];
```

**字段说明：**

| 字段 | 必须 | 说明 |
|------|------|------|
| `modulename` | 是 | 模块中文名称，显示在后台模块列表 |
| `version` | 是 | 版本号，仅数字和点号 |
| `adaptation` | 是 | 适配的最低 CMS 版本，安装时系统会校验 |
| `depend` | 否 | 依赖的其他模块列表，安装前检查是否已安装 |
| `icon` | 否 | 模块图标 URL |
| `introduce` | 否 | 模块简要介绍 |
| `author` | 否 | 作者名 |
| `sign` | 否 | 模块签名 |

### install/Menu.php（可选）

定义模块在后台管理界面的菜单结构。菜单支持多级嵌套。

```php
<?php

return [
    [
        // 父菜单ID：0 表示顶级菜单，NULL 使用系统默认
        "parentid" => 0,
        // 路由：模块/控制器/方法
        "route"    => "demo/index/index",
        // 类型：0=纯菜单，1=权限认证+菜单
        "type"     => 0,
        // 显示状态：1=在后台菜单栏显示，0=不显示
        "status"   => 1,
        // 菜单名称
        "name"     => "示例",
        // 备注
        "remark"   => "",
        // 子菜单（递归结构）
        "child"    => [
            [
                "route"  => "demo/admin.page/list",
                "type"   => 1,
                "status" => 1,
                "name"   => "列表页",
                "remark" => "",
                "child"  => []
            ],
        ]
    ]
];
```

**菜单字段说明：**

| 字段 | 说明 |
|------|------|
| `parentid` | `0` = 顶级菜单；`NULL` = 挂在系统"模块"菜单下 |
| `route` | 格式为 `模块名/控制器/方法`，子目录控制器用 `.` 分隔，如 `demo/admin.page/list` |
| `type` | `0` = 只作为菜单显示；`1` = 同时注册为权限节点 |
| `status` | `1` = 在后台左侧菜单栏展示；`0` = 不展示（适用于编辑、删除等操作权限） |
| `child` | 子菜单数组，支持无限层级嵌套 |

### install/{ModuleName}.sql（可选）

模块安装时执行的数据库建表脚本。

**命名规则：** 文件名为模块名首字母大写，如 `Wechat.sql`、`Common.sql`。

**编写规范：**
- 表名统一使用 `cms_` 前缀（系统安装时会自动替换为实际配置的表前缀）
- 使用 `CREATE TABLE` 语句
- 每条 SQL 以 `;` 结尾并换行
- 注释行以 `#` 或 `-` 开头

```sql
CREATE TABLE `cms_example_data`
(
    `id`          int(11) unsigned NOT NULL AUTO_INCREMENT,
    `title`       varchar(255) DEFAULT '' COMMENT '标题',
    `content`     text COMMENT '内容',
    `create_time` int(11) DEFAULT '0' COMMENT '创建时间',
    `update_time` int(11) DEFAULT '0' COMMENT '更新时间',
    `delete_time` int(11) DEFAULT '0' COMMENT '删除时间',
    PRIMARY KEY (`id`) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### uninstall/{ModuleName}.sql（可选）

模块卸载时执行的数据库清理脚本。

**命名规则：** 与安装 SQL 同名，如 `Wechat.sql`。

```sql
DROP TABLE IF EXISTS `cms_example_data`;
```

> 卸载 SQL 应与安装 SQL 对应，删除所有安装时创建的表。

### middleware.php（可选）

模块级别的中间件配置，仅对本模块下的请求生效。

```php
<?php
return [
    \app\common\middleware\Cors::class,
];
```

### cronscript/（可选）

定时任务脚本目录，脚本类需继承 `app\common\cronscript\CronScript` 基类。

```php
<?php
namespace app\example\cronscript;

use app\common\cronscript\CronScript;

class CleanDataScript extends CronScript
{
    public function run($cronId)
    {
        // 执行定时任务逻辑
        return self::createReturn(true, ['cleaned' => 100]);
    }
}
```

### job/（可选）

队列任务目录，任务类需继承 `app\common\libs\queue\BaseQueueJob` 基类。

## 开发规范

### 目录命名

- 模块目录名使用**全小写**字母
- SQL 文件名使用模块名**首字母大写**（如 `Wechat.sql`）

### 数据库表命名

- 表名统一使用 `cms_` 前缀
- 格式：`cms_{模块名}_{功能名}`，如 `cms_wechat_office_user`
- 使用下划线命名法

### 控制器命名

- 后台控制器放在 `controller/admin/` 或 `controller/` 下，继承 `app\common\controller\AdminController`
- API 控制器继承 `app\api\controller\BaseApi`
- 路由格式：`模块名/控制器/方法`，子目录用 `.` 分隔（如 `wechat/open.AuthorizerAdmin/list`）

### 服务层

- 服务类继承 `app\common\service\BaseService`
- 统一返回格式：`self::createReturn($status, $data, $msg, $code)`
